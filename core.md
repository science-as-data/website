<section aria-labelledby="outcomes"><h2 id="outcomes">Completed work</h2>
<p>These are historical load totals reported in the repository’s <a href="https://github.com/science-as-data/core/blob/main/docs/INGESTION.md">ingestion documentation</a> and <a href="https://github.com/science-as-data/core/blob/main/docs/COMPLETENESS_ASSESSMENT.md">5 June 2026 completeness assessment</a>. They have not been refreshed from the database for this page.</p>
<ul><li><strong>Ingestion:</strong> snapshot discovery and download, PostgreSQL provisioning, streaming archive-to-table loading, restart support, and post-load indexing.</li><li><strong>Parsing:</strong> a Julia library for record and XML-manifest parsing, with fixture-based tests and tolerance for missing fields and alternate source shapes. The bulk loader uses a separate Python streaming parser.</li><li><strong>Assessment:</strong> a local metadata baseline, per-year and document-type comparisons against the API, and sampled record-survival and field-drift checks.</li></ul>
<p>The batch accounting covers all 137 archives. The documented resumed run processed 182,266,035 records with 10 malformed JSON records skipped; the error total for the earlier 19 batches is not available. Batch completion therefore does not establish zero record loss.</p></section>
<section aria-labelledby="data"><h2 id="data">What the data contain</h2><p>Records combine bibliographic metadata with repository identifiers and, for a subset, extracted text. Titles, abstracts, publication years, languages, document types, publishers, DOI/OAI identifiers, journal details, and download links support discovery and analysis. Subjects, topics, relations, contributors, and other nested fields remain available in JSONB when supplied.</p>
<p><strong>About 11.99% of works have stored full text.</strong> A download link is a separate field and does not imply the text is present locally. Author rows preserve names and order; they are not disambiguated researchers. One CORE ID defines the database’s work unit, which should not be assumed to be a perfect unique-paper identity across catalogs.</p>
<p>Publication dates are retained as text because source values are irregular; year is a separate nullable integer. These fields require validation before temporal analysis. The source batch label records where each work came from.</p></section>
<section aria-labelledby="schema"><h2 id="schema">Four linked tables</h2><div class="data-table-scroll"><table><thead><tr><th scope="col">Table</th><th scope="col">Contents and relationship</th></tr></thead><tbody>
<tr><th scope="row"><code>works</code></th><td>One row per <code>core_id</code>, with frequently queried scalar fields, a full-text flag, and source batch.</td></tr>
<tr><th scope="row"><code>works_fulltext</code></th><td>At most one extracted text per work; large text is stored separately from metadata.</td></tr>
<tr><th scope="row"><code>works_authors</code></th><td>Multiple ordered author names per work, keyed by <code>core_id</code> and <code>ord</code>.</td></tr>
<tr><th scope="row"><code>works_doc</code></th><td>One JSONB object per work containing source values except <code>fullText</code>, which is kept in its own table. JSON formatting and key order are not preserved.</td></tr>
</tbody></table></div><p>Foreign keys connect the three child tables to <code>works</code>. Separating full text keeps metadata queries from carrying large text values. <a href="https://github.com/science-as-data/core/blob/main/scripts/03_schema.sql">Read the database schema</a>.</p></section>
<section aria-labelledby="coverage"><h2 id="coverage">Coverage and missing metadata</h2><p>The historical local baseline used a 0.2% page sample of 443,186 rows. The following percentages are <strong>sample estimates</strong>, not exact whole-table counts or guarantees of identifier validity.</p>
<div class="data-table-scroll"><table><thead><tr><th scope="col">Field availability</th><th scope="col">Estimated share of works</th></tr></thead><tbody><tr><th scope="row">DOI present</th><td>42.72%</td></tr><tr><th scope="row">OAI identifier present</th><td>58.01%</td></tr><tr><th scope="row">At least one DOI or OAI identifier</th><td>86.41%</td></tr><tr><th scope="row">Neither identifier</th><td>13.59%</td></tr><tr><th scope="row">Publication year present</th><td>67.68%</td></tr></tbody></table></div>
<p>In the June 2026 assessment, local-to-API count ratios varied strongly by publication year: 38.2% for 2020 and 13.0% for 2023. The study also found historical backfill in older years. These ratios compare two populations at different dates; they are not row-level match rates. The dump is not a current mirror of CORE, and missing years limit temporal comparisons.</p><p>For the API comparison used in that assessment, DOI and OAI were lookup keys; the API and dump used different CORE identifier spaces. Identifier absence restricted those row-level checks. Candidate linkage to publications from other sources is documented under <a href="/data-matching/">Data matching</a>.</p></section>
<section aria-labelledby="next"><h2 id="next">Remaining work</h2><p>The repository’s latest documented completeness assessment remains in progress: Phase A (local baseline) and Phase B (API population comparisons) are complete; Phase C has sampled survival/drift results; Phase D (field-fill comparison) remains outstanding. Open work includes broader survival samples, field-fill comparisons, and understanding which providers and document types dominate records without usable lookup keys. The snapshot and API comparison dates should travel with any derived results.</p><p><a href="https://github.com/science-as-data/core/blob/main/docs/COMPLETENESS_ASSESSMENT.md">Assessment, evidence, and caveats</a> · <a href="https://github.com/science-as-data/core/blob/main/docs/COVERAGE.md">Coverage tooling</a></p></section>
